# 演示脚本（6 分钟版）

> 一句话定位：把采购需求报告丢进来，几分钟内产出**结构化字段 + 审核报告 + 可编辑的招标文件初稿**，
> 并顺手给出**投标书初稿**与**废标风险清单**。所有值带原文证据，模型不编造。

## 1. 演示前 10 分钟预检

| # | 检查项 | 动作 | 通过标准 |
|---|--------|------|----------|
| 1 | 服务 | `start.bat web`，或双击 `dist\招标需求解析.exe` | 打开 `http://127.0.0.1:8765/` 正常 |
| 2 | 模型 | `ollama serve` 已在跑 | 页面右上角模型状态为「可用」 |
| 3 | 企业档案 | 打开 `/company` | 已有「演示科技有限公司」（虚构演示数据，2 资质 / 2 业绩 / 2 人员） |
| 4 | 预跑任务 | 打开 `/?job=09430870a68f42d98fdf23868e1450bd` | 能看到 16 个字段、12/46 模板覆盖、7 条复核 |
| 5 | 浏览器标签 | 首页、预跑任务、`/fill.html?job=09430870a68f42d98fdf23868e1450bd`、`/projects`、`/company` | 五个标签按演示顺序排好 |
| 6 | PDF | 本机有 LibreOffice 或 Word | 点「导出 PDF」能出文件；没有则跳过（见兜底） |

**为什么必须预跑**：完整链路（规则 + 7B 模型 + 校验回喂）在演示机上实测约 3 分 20 秒。
现场不要等模型，用「仅规则」演示流程，再用预跑任务讲模型补缺与复核。

## 2. 分镜

### 0:00–0:40｜痛点

- 页面：`/`（首页，先不传文件）
- 台词：采购人写需求报告、代理机构再手工录进招标文件，同一份信息抄两遍；字段漏一个，后面就是质疑和废标风险。
- 落点：这个组件做两件事——**把报告读成结构化字段**，**把字段写回标准招标文件**。

### 0:40–2:00｜解析：规则先跑，模型补缺

- 操作：拖入 `data/采购需求样本/2025年社区管理与服务专业教学资源库委托服务项目需求报告.docx`，
  模式切到**「仅规则（不调用模型，更快）」**，点开始。
- 台词：规则层先把项目名称、预算、采购标的、付款分期这些能从原文直接读到的字段读出来，几秒完成；模型只负责补规则读不到的。
- 页面：结果页 →「字段」页，指一个字段的**原文证据**（block_id + 引文）。
- 切到预跑任务标签：指 `16 个字段 / 12 项模板覆盖 / 7 条复核`，说明这是**完整链路**的结果。
- 台词：模型补的每个值都要能回链原文，回链不上就丢弃；规则和模型不一致时两个候选都留着，标记冲突，不静默覆盖。

### 2:00–3:20｜填写页：把「人工核对」做成可操作的

- 操作：点「去填写招标文件 →」。
- 依次指出三种提示条：
  - 蓝色/原文抽取：直接来自原文；
  - 绿色「上次填」：上一个项目确认过的采购人/代理机构，点「采用」秒填（字段资产复利）；
  - 黄色「AI 建议」：原文没有、模板需要的合同条款类字段，点「采纳建议」才写入。
- 点「从标的清单导入」：把需求报告里多行标的（数量/单价/金额/要求摘要）一次导入。
- 台词：AI 建议在采纳前**不写入抽取结果、不参与模板回填**，避免模型编造污染事实层。

### 3:20–4:10｜生成招标文件

- 操作：点右上角「生成招标文件」→ 下载 `.docx`，用 Word 打开。
- 台词：回填的是广东省政府采购公开招标标准模板；缺失字段写「待补充」，不猜。
- 指几处占位符已替换（项目名称、预算、采购方式、付款方式）。
- 若机器有转换器：点「导出 PDF」，说明 LibreOffice/Word 自动探测。

### 4:10–5:10｜投标书 + 图谱：从「写文件」走到「帮投标人」

- 操作：回结果页，点「生成投标书初稿」。
- 台词：读取企业档案，资格条款逐条映射证明材料并标出缺口；评分点起草技术方案；★条款转成提交前自查清单。
- 操作：点「图谱风险分析」。
- 台词：抽取结果 + 关系抽建成 RDF 图，三类清单——符合性自查、废标预警、评分点材料映射；`.ttl` 可直接用 Protégé 打开。
- 指风险清单：模型没抽到废标条款时，自动回退到规则层的「★ 实质性条款」，所以清单不会是空表（`meta.fallbacks` 标明来源）。

### 5:10–6:00｜项目工作台与交付形态

- 操作：`/projects` → 打开演示项目 →「导出项目 zip」。
- 台词：zip 内含每个任务的结果 JSON、审核报告、平台草稿和招标文件 docx，可直接归档或交给代理机构。
- 收尾：整个组件可打包成单文件 exe，双击即跑，数据落在 exe 同目录 `data/`，拷给不装环境的同事也能用；默认只连本机 Ollama，文档不出内网。

## 3. 兜底话术

| 现场情况 | 处理 |
|----------|------|
| 模型响应慢 | 不等，切「仅规则」；用预跑任务讲模型补缺。台词：「模型是补缺，不是必经路径，规则层已能出文件。」 |
| 模型不可用 | 页面会显示不可用原因；直接跑「仅规则」，说明可切 OpenAI 兼容接口或内网网关。 |
| PDF 导出 409 | 台词：「PDF 依赖本机 LibreOffice 或 Word，没有就交付 docx；docx 是代理机构真正要改的格式。」 |
| 企业档案被清空 | `/company` 现场录入 1 条资质 + 1 条业绩即可，30 秒。 |
| 现场断网 | 全部本地，不影响；只要 Ollama 已加载过模型。 |

## 4. 预判提问

- **准确率多少？** 真实样本规则层 14 个字段有值、模板覆盖 13/46；模型补缺后 8 个字段规则+模型一致确认、0 校验错误。准确率不靠“模型说对”，靠证据回链 + 校验 + 人工复核三层。
- **和平台什么关系？** 可作为平台后端抽取部件（`recognize_to_draft` 直接产出平台草稿 JSON），也可以独立出文件。
- **数据安全？** 默认 `provider=ollama`，不出本机；只有显式切换 API 才发送文档片段。
- **为什么不用微调？** 招标文件版式变化大、字段规则明确，规则 + 少样本提示 + 校验回喂的迭代成本远低于微调，且每个值可追溯。
- **能处理扫描件吗？** 无文字层的 PDF 需先 OCR；当前支持 docx / 有文字层 pdf / txt。

## 5. 演示数据说明

- 企业档案「演示科技有限公司」及其资质、业绩、人员均为**虚构演示数据**，正式使用前在 `/company` 替换。
- 预跑任务 `09430870a68f42d98fdf23868e1450bd` 使用 `data/结果审核报告/uploads/` 内的脱敏需求报告，服务重启后仍可从 SQLite 恢复。
- 演示前建议清空浏览器缓存以外的页面状态：直接刷新标签页即可；任务与字段确认值都在本地 `data/tender.db`。
