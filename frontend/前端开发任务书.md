## 1. 开工前必读

### 1.1 这个产品是什么

输入采购需求报告（.docx/.pdf/.txt）→ 输出结构化字段 JSON + 审核报告 + **可编辑的招标文件 .docx**。你要改的是最后一环的用户界面。

页面与入口（左侧导航由 `frontend/shell.js` 统一注入）：

| 页面 | 路径 | 与你这次任务的关系 |
|---|---|---|
| 需求解析 | `/` | 上传、看结果，不改 |
| 填写工作台 | `/fill` | **任务 2、3 的主战场** |
| 文档比对 | `/compare` | 不改 |
| 项目工作台 | `/projects` | 不改 |
| 企业档案 | `/company` | 不改 |
| 设置 | `/settings` | 不改 |
| 模板库 | `/templates`（**新增**） | **任务 1 的主战场** |

### 1.2 跑起来

```powershell
# 项目根目录
start.bat web
# 或
python -m tender_extractor.web --no-browser --port 8765
```

打开 `http://127.0.0.1:8765`。改 `frontend/` 下的文件后**刷新浏览器即生效**，不用重启服务（响应头是 `Cache-Control: no-store`）。

页面由后端托管，所以访问地址是 `/fill` 而不是 `file:///.../fill.html`；直接双击 html 会拿不到接口数据。

### 1.3 三条不能破的约束

违反任何一条，功能做得再好也不合格：

1. **零第三方 Web 依赖**：不引 CDN、不引 npm 包、不上框架（React/Vue）、不上构建工具。纯 HTML/CSS/JS，图标一律内联 SVG。
2. **无外部请求**：页面里不得出现向外部域名发起的请求（字体、图表库、埋点都不行），产品定位是「文档不出本机」。
3. **不改 API 契约**：`/api/*` 的路径与字段结构以 `src/tender_extractor/web.py` 为准。需要新接口时提给后端，由后端实现并同步 `frontend/README.md`，前端按契约表对接。

样式一律复用 `frontend/app.css` 的设计系统（`--ink`、`--muted`、`--line`、`--surface`、`--green`、`--amber`、`.btn`、`.card`、`.tbl`、`.tag`、`.notice`、`.seg`、`.chip`），**不要另写一套配色**。

### 1.4 分支与提交

沿用 `DEVELOPMENT.md` 8.2.1：从 `main` 开临时分支 → 提交 → `git push -u origin <分支>` → 在 GitHub 开 PR（base 为 `main`）→ review 后 Squash merge → 删分支。**不要直接往 `main` 提交。**

分支命名：

| 任务 | 分支 |
|---|---|
| 任务 1 | `feature/frontend-template-library` |
| 任务 2 | `feature/frontend-preview` |
| 任务 3 | `feature/frontend-custom-fields` |

PR 描述四行：改了什么 / 为什么 / 怎么验证（附截图与操作步骤）/ 影响面（是否动了接口）。

## 2. 现状盘点（别重复造轮子）

### 2.1 已有的、可以直接用的

| 能力 | 位置 | 说明 |
|---|---|---|
| 字段视图接口 | `GET /api/jobs/{id}/fields` | 按 `basic/party/award/inquiry/scoring/contract` 六组返回字段，含 `label/template/value/confidence/status/evidence/history/na` |
| 历史值复用 | 同上 `item.history` | 绿色提示条「上次填写…采用」已实现 |
| AI 起草缺失字段 | `POST /api/jobs/{id}/suggest` | 只出建议（黄色提示条），人工点「采纳」才写入 |
| 生成招标文件 | `POST /api/jobs/{id}/generate` | 入参 `{values:{占位符名→值}, missing_mode}`，回 `.docx` 二进制 |
| PDF 导出 | `POST /api/jobs/{id}/export/pdf` | 依赖本机 LibreOffice 或 Word，**不可用作预览主通道**（见 4.2） |
| 模板源文件 | `templates/广东省政府采购公开招标标准模板.docx` | 单花括号占位符 `{项目名称}` |
| 渲染用模板 | `templates/compiled/*.docx` | 由 `scripts/prepare_template.py` 转成 jinja2 语法的**产物**，不要手改 |
| 字段定义 | `src/tender_extractor/config/fields.json` | 53 个字段，`fields[].template` 就是占位符名 |

### 2.2 缺的、这次要补的

| 缺口 | 影响 |
|---|---|
| 模板路径写死在 `doc_generator.DEFAULT_TEMPLATE`，`Service.generate_document` 不接受模板参数 | 只能生成一种版式 |
| 没有模板列表/上传/删除的接口与页面 | 用户无法管理模板 |
| 生成是「点一下直接下载 blob」 | 看不到成品，改错字段要重新生成才能发现 |
| 字段清单只来自 `fields.json` | 用户加不了字段；前端强行加一个输入框也不会出现在文档里（原因见 5.2） |

### 2.3 已知缺陷（本次一并修，别绕过）

| # | 位置 | 问题 | 修法 |
|---|---|---|---|
| P0-1 | `fill.html` 的 `collectValues()` | 它遍历 `document.querySelectorAll(".field")`，而工作台**一次只渲染一个分组**，所以切过分组后点生成，前面分组里「清空/修改」的值不会被提交（后端回落到 AI 原始值） | 值来源改为 `state[key] ?? item.value` 全量合并，DOM 只负责展示 |
| P0-2 | `fill.html` 的 `fieldHtml()` 里 `groupsData.groups` | `groupsData` 是数组，`groupsData.groups` 恒为 `undefined`，导致「从标的清单导入」按钮永远不出现 | 改为 `groupsData.flatMap(g => g.items)` |
| P1-1 | `fill.html` 的 `filter === "todo"` 判断 | 条件里 `st.mode === "ai"` 实际永远不成立（`mode` 只有 `edited/accepted/cleared/history`），「待处理」筛选语义不准 | 与产品确认后重写筛选逻辑 |

## 3. 任务一：模板库扩展

### 3.1 需求

当前只有一套「广东省政府采购公开招标标准模板」。目标：

1. 支持**多套模板**并存：货物 / 服务 / 工程 × 公开招标 / 竞争性磋商等，每套模板有名称、适用品目、采购方式、版本。
2. 支持**上传自有模板**（.docx，占位符写法为 `{XXX}`）。
3. 上传后自动分析：这套模板有哪些占位符、哪些已经能对应到现有字段、哪些是新出现的（需要用户处理）。
4. 填写工作台里能**选模板**，生成时用选中的那套。
5. 能设默认模板、删除模板。

> 背景：`DEVELOPMENT.md` 已把它列为下一阶段第 2 项，依赖是「先拿到各类模板原件」。没有新原件时，先用自有模板上传跑通流程，页面不能做成空壳。

### 3.2 数据与接口（由后端实现，前端按此对接）

模板文件一律放**用户数据目录** `data/templates/<template_id>/`，不要放仓库的 `templates/`（`templates/` 进 git，用户上传的模板可能包含真实单位信息）。

```
data/templates/<template_id>/
├── source.docx     # 用户上传原件（单花括号占位符）
├── compiled.docx   # prepare_template 转换后的 jinja2 版
└── meta.json       # 元信息
```

`meta.json`：

```json
{
  "id": "tpl-20261104-a1b2c3",
  "name": "广东省政府采购公开招标标准模板（服务类）",
  "category": "service",
  "method": "open",
  "version": "1.2.0",
  "source_filename": "某省政府采购模板.docx",
  "created_at": "2026-11-04T10:12:00",
  "is_default": true,
  "placeholders": ["项目名称", "采购项目编号", "预算金额"],
  "unmapped": ["采购人邮箱", "履约保证金比例"],
  "missing_fields": ["合同份数"]
}
```

字段含义：
- `placeholders`：模板里**全部**占位符名（去重）。
- `unmapped`：模板里有、但 `fields.json` 里没有任何字段的 `template` 与之一致的占位符 → 生成时会留「待补充」，需要用户处理。
- `missing_fields`：`fields.json` 里声明了 `template` 名，但模板里没有这个占位符 → 说明模板与字段集不匹配，属于健康警告。

接口：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/templates` | 列表：`{"templates":[meta…]}`，`is_default` 唯一 |
| POST | `/api/templates?filename=xxx.docx` | 上传模板，body 为文件二进制（与 `/api/extract` 同风格，不用 multipart）；返回新 meta 与解析告警 |
| GET | `/api/templates/{id}` | 详情（meta + `placeholders` 明细：哪些已映射到哪个 `field.key`） |
| POST | `/api/templates/{id}/rename` | `{"name":"…"}`，重命名 |
| POST | `/api/templates/{id}/default` | 设为默认 |
| DELETE | `/api/templates/{id}` | 删除；删默认模板时自动回退到内置模板 |
| GET | `/api/templates/{id}/preview` | 空值预览，返回与 4.3 相同的 `blocks` 结构（模板里所有占位符显示为「待补充」） |

上传失败必须给出**人话错误**，前端直接展示：非 .docx、文件损坏、模板里一个 `{占位符}` 都没有（大概率传错了文件）、占位符超过 30 字（渲染器限制）。

### 3.3 前端页面 `/templates.html`

新增文件：`frontend/templates.html`（页面结构、样式、脚本同页内联，与 `fill.html` 保持一致的组织方式；若逻辑超过 300 行再拆 `templates.js`）。

同时要改：

1. `shell.js` 的 `ITEMS` 增加一项：`{ href: "/templates", label: "模板库", icon: "templates" }`，并补一个内联 SVG 图标。
2. 提醒后端在 `web.py` 的 `do_GET` 里加路由：`/templates`、`/templates.html` → `_serve_static("templates.html")`。**这一步前端改不了，写进联调清单。**

页面结构：

```
页头：模板库                         [上传模板]
说明：一套模板对应一种采购品目与采购方式的成稿版式…

模板卡片网格（每卡）：
  ┌────────────────────────────────────────────┐
  │ 广东省政府采购公开招标标准模板（服务类）  默认 │
  │ 服务类 · 公开招标 · v1.2.0                  │
  │ 占位符 87 个 · 未匹配字段 2 个              │
  │ 上传于 2026-11-04                           │
  │ [预览] [设为默认] [重命名] [删除]            │
  └────────────────────────────────────────────┘
```

交互要求：

| 场景 | 要求 |
|---|---|
| 空态 | 不能是白屏。显示内置模板卡片 + 「上传你自己的模板」说明，讲清占位符写法 `{项目名称}` |
| 上传中 | 按钮 loading、禁止重复点击；超过 10 秒给「模板较大，正在解析占位符…」 |
| 上传成功 | toast + 卡片插入列表顶部；若 `unmapped` 非空，顶部出现黄色提示条：「有 N 个占位符没有对应字段，点此处理」 |
| 未匹配占位符 | 卡片内展开清单，每项右侧按钮「创建字段」→ 直接打开任务 3 的添加字段弹窗，字段名预填占位符名、写入位置预选「绑定该占位符」 |
| 删除 | 二次确认弹窗（`.dlg`），文案说明「删除后已生成的文件不受影响」；删除默认模板时提示「将回退到内置模板」 |
| 重命名 | 行内或弹窗改为可编辑；空名、重名要拦 |
| 预览 | 打开预览抽屉，用 4.4 的渲染规则显示这套模板的空壳（全部占位符高亮为「待补充」） |

分类与采购方式的显示值统一在 `frontend/templates.html` 里用一个映射表：

```js
var CATEGORY = { goods: "货物", service: "服务", works: "工程", other: "其他" };
var METHOD = {
  open: "公开招标", invite: "邀请招标",
  negotiation: "竞争性磋商", inquiry: "询价",
  single: "单一来源", other: "其他"
};
```

后端返回未知枚举值时，原样显示枚举字符串，**不要显示成空白**。

### 3.4 填写工作台接入模板选择

`/fill` 页头 `fileInfo` 下面加一行：

```
当前模板：广东省政府采购公开招标标准模板（服务类） · 87 个占位符    [切换]
```

- 默认取任务的抽取结果对应的模板（v1 就是默认模板）。
- 点「切换」弹出模板选择器（列表 + 预览按钮），选中后**当前填写值不丢**，只影响生成与预览。
- 切换后如果新模板的占位符集合与旧的不同，给一次提示：「新模板里有 N 个占位符没有字段，生成的文档会显示『待补充』」。这个 N 由 `/api/templates/{id}` 的 `unmapped.length` 得来。
- 选择结果存 `localStorage`：`tender.templateId.<jobId>`，刷新页面保持。
- 生成时把 `template_id` 一起提交（见 6.1）。

### 3.5 验收标准

1. 上传 2 个不同模板后，列表出现 3 张卡片（含内置），刷新页面不消失。
2. 上传一个没有 `{占位符}` 的 .docx，页面给出明确错误提示，不产生半成品卡片。
3. 把模板 B 设为默认 → 卡片上的「默认」标记转移，刷新后仍为 B。
4. 在 `/fill` 选模板 B 生成，下载的文件**版式是 B 的**（用 Word 打开对比标题/表格结构）。
5. 删除模板 B 后，`/fill` 选择器里不再出现 B，生成回落到默认模板且不报错。
6. 未匹配占位符点「创建字段」，弹窗字段名已预填。

## 4. 任务二：生成前预览

### 4.1 需求

现在点「生成招标文件」是直接下载 `.docx`，用户必须用 Word 打开才知道好不好。目标：

1. 在填写工作台里，点「预览」能在页面上看到**成品的样子**：章节顺序、表格、每处字段值。
2. 没填的字段在预览里高亮为黄色「待补充」，并统计条数。
3. 点击预览里的任一字段值 → 左侧字段列表滚动到该字段并高亮，方便就地改。
4. 预览只读，不改文档；要下载仍走「生成并下载」。

明确不做：不做所见即所得编辑（不在预览里直接改字，v1 不支持）、不做拖拽排版。

### 4.2 方案选型（为什么不用 PDF）

现状：后端有 `docx → PDF`（LibreOffice / Word COM），但 `_send_binary()` 的响应头固定 `Content-Disposition: attachment`，iframe 里打不开；而且**本机不一定装了 LibreOffice 或 Word**，生成一份 PDF 要 2–10 秒。把预览建立在它上面，等于把「基础功能」绑在「可选依赖」上。

因此采用**结构化 blocks 预览**：

```
后端 python-docx 读 compiled 模板 → 占位符替换为当前值 → 输出结构化 JSON（段落/表格/样式/片段）
前端按纸张样式渲染成 HTML
```

优点：零新依赖、毫秒级、每个片段都带占位符名，能精确做「点击定位」。缺点：字体、页边距、分页是 CSS 近似，不是 Word 真实排版——所以预览页面上必须有一行小字说明：

> 预览为结构近似，字体与分页以生成的 .docx 为准。

如果后续需要像素级还原，再单独加「精确预览（PDF）」按钮，走 `inline` 下载头 + 本机转换器检测（本机没有转换器时按钮置灰并说明原因）。**v1 不做。**

### 4.3 接口契约

```
POST /api/jobs/{id}/preview
Content-Type: application/json

{
  "template_id": "tpl-20260401-xxxx",   // 可选，缺省用默认模板
  "values": { "项目名称": "…", "采购项目编号": "" },   // 当前编辑值，键为占位符名
  "missing_mode": "mark",               // mark | empty
  "custom_fields": [ … ]                // 可选，见 5.6
}
```

响应：

```json
{
  "template": { "id": "…", "name": "广东省政府采购公开招标标准模板（服务类）" },
  "stats": { "total_placeholders": 87, "filled": 71, "missing": 16 },
  "missing": ["采购项目编号", "代理机构地址"],
  "sections": [
    {
      "title": "第一章 投标邀请",
      "blocks": [
        {
          "type": "paragraph",
          "style": "title",
          "segments": [
            { "kind": "text",  "text": "项目名称：" },
            { "kind": "value", "text": "2025年某某服务项目", "name": "项目名称" },
            { "kind": "text",  "text": "  项目编号：" },
            { "kind": "missing", "text": "【待补充：采购项目编号】", "name": "采购项目编号" }
          ]
        },
        {
          "type": "table",
          "rows": [
            [
              { "colspan": 1, "rowspan": 1, "segments": [ { "kind": "text", "text": "序号" } ] },
              { "colspan": 1, "rowspan": 1, "segments": [ { "kind": "text", "text": "采购标的" } ] }
            ]
          ]
        }
      ]
    }
  ],
  "warnings": []
}
```

契约要点（前端要按此容错）：

| 字段 | 规则 |
|---|---|
| `style` | 枚举：`title` / `h1` / `h2` / `h3` / `body`。后端负责把 Word 的「标题 1」「Title」等中文样式名归一化到这个枚举；无法识别一律给 `body`。前端遇到不认识的值也按 `body` 渲染，不报错 |
| `segments[].kind` | `text`（原文） / `value`（有值） / `missing`（待补充）。只有后两种带 `name` |
| 表格单元格 | 必有 `colspan`/`rowspan`；被合并覆盖的位置返回 `{"skip": true}`，前端跳过不渲染，避免表格错位 |
| `sections` | 后端按章切分；**切不出来时允许只返回一个 section**，前端不能依赖章节数 |
| `stats.missing` 与 `missing[]` | 用于「缺 16 项」提示条与「只看缺失」跳转 |
| 错误 | 任务不存在 404、任务未完成 409、模板不存在 400，body 均为 `{"error":"人话"}` |

### 4.4 渲染规则

新建一个预览面板（容器 `#previewPane`），内部是纸张：

```css
.paper {
  width: 210mm; min-height: 297mm;
  padding: 20mm 18mm;
  background: #fff; color: #111;
  box-shadow: var(--sh-2);
  font-family: "SimSun", "宋体", serif;
  font-size: 12pt; line-height: 1.75;
  margin: 0 auto;
}
.paper .seg-missing { background: var(--amber-soft); border-bottom: 1px dashed var(--amber-line); cursor: pointer; }
.paper .seg-value[data-name] { cursor: pointer; }
.paper .seg-value[data-name]:hover { background: var(--blue-soft); }
```

样式映射：

| `style` | 渲染 |
|---|---|
| `title` | 居中，22pt，加粗，下边距 18pt |
| `h1` | 16pt，加粗，上边距 18pt 下边距 10pt |
| `h2` | 14pt，加粗，上边距 14pt 下边距 8pt |
| `h3` | 12.5pt，加粗，上边距 10pt 下边距 6pt |
| `body` | 首行缩进 2em，两端对齐 |
| `table` | `border-collapse: collapse`，`td` 1px 实线边框、`padding: 4pt 6pt`、`font-size: 10.5pt`、垂直居中 |

其他硬性要求：

- **不要用 iframe 加载后端 HTML**：后端只给 JSON，HTML 由前端拼，样式才能跟 `app.css` 一致。
- 所有文本走 `esc()` 转义（现有 `fill.html` 里已有该函数），禁止 `innerHTML` 直接拼后端字符串。
- 空白段落在 Word 里有意义（空行），`segments` 为空数组时渲染 `<p>&nbsp;</p>`，不要丢掉。
- 表格列宽按后端给的 `colspan` 等分即可，v1 不还原 Word 的列宽。

### 4.5 交互与性能

| 项 | 要求 |
|---|---|
| 布局 | `≥1280px`：三栏（分组导航 196 / 字段区 minmax(0,1fr) / 预览 480）。`960–1280`：预览改为右侧抽屉（宽 480，可关闭）。`<960`：改为 Tab 切换「填写 / 预览」 |
| 触发 | 首次点「预览」请求一次；之后字段输入 `debounce 800ms` 再刷新。切换分组不触发 |
| 加载 | 请求中纸张区域显示骨架/遮罩，不要闪白；失败显示错误 + 「重试」 |
| 定位 | 点 `seg-value` / `seg-missing` → 若该字段不在当前分组，先切分组 → `scrollIntoView({block:"center"})` → 目标字段加 1.5 秒的临时高亮类 |
| 顶部提示 | 预览面板头部：`已填 71 / 87 项 · 待补充 16 项`，右侧「只看缺失」开关（开启时预览里只保留含 `missing` 的段落/表格行，并保持章节树可见） |
| 生成入口 | 预览面板底部固定一条操作区：「生成并下载 .docx」。避免用户在长预览里往回找按钮 |
| 状态记忆 | 面板开合状态存 `localStorage`，不要每次进页面都重新打开 |

### 4.6 验收标准

1. 修改「项目名称」→ 800ms 后预览里同步变化，无需生成文件。
2. 清空某字段 → 预览对应位置变黄底「待补充」，顶部计数 +1。
3. 点击预览里某个黄色「待补充」→ 左侧字段区切到该字段并居中高亮。
4. 切到另一个分组再点生成，前面分组的修改**没有丢**（同时验证 P0-1 已修）。
5. `missing_mode=empty` 时预览不出现「待补充」字样，对应位置为空。
6. 表格类内容（商务要求表、标的清单、技术参数附表）在预览里是表格，不塌成一行文字。
7. 500 页级别的模板打开预览不卡死（前端渲染耗时 < 1s，可接受分节懒渲染，但不要做无边界优化）。

## 5. 任务三：填写工作台自定义字段

### 5.1 需求

内置字段固定 53 个（`fields.json`）。真实项目里总有模板特有的项（例如「履约保证金比例」「采购人邮箱」「现场踏勘时间」）。目标：

1. 用户可以在填写工作台**新增自定义字段**：字段名、值、类型、写入位置。
2. 自定义字段参与进度统计、可编辑、可删除。
3. 生成招标文件时，自定义字段的内容**真的出现在文档里**。
4. 刷新页面后自定义字段还在。

### 5.2 关键设计决策（先看这段，否则会做错）

**不能只在前端加一个输入框。** 原因：

- 后端 `generate_tender_document()` 只处理模板里存在的占位符：`values` 里多出来的键会被忽略（它按 `template_names()` 求交集生成 `context`）。
- 所以「页面上加了个输入框 → 生成时消失」是必然结果。

正确的做法是把自定义字段分成两类，分别有明确的落点：

| 类型 | 落点 | 适用场景 |
|---|---|---|
| **A. 绑定模板占位符** | 写入模板里已存在、但 `fields.json` 没定义字段的占位符（即任务 1 的 `unmapped`） | 模板里有 `{采购人邮箱}`，字段集里没有 |
| **B. 追加补充条款** | 生成时在文档末尾追加一节「补充条款」，两列表格：字段名 \| 内容 | 模板里根本没有这一项，但用户想补进成稿 |

**不要**做「在文档任意位置插入」：需要段落级定位与 Word 风格复制，v1 收益远低于成本。

### 5.3 数据模型

前端内存中：

```js
// 一条自定义字段
{
  key: "cf_1",                 // 前端生成，前缀 cf_ + 时间戳/自增，永不复用
  label: "履约保证金比例",
  value: "合同金额的 5%",
  type: "text",                // text | long_text | money | date | select
  options: [],                 // type=select 时的候选
  target: "append",            // append | placeholder
  placeholder: "",             // target=placeholder 时必填，来自模板 unmapped 列表
  created_at: "2026-11-04T10:30:00"
}
```

持久化：

- 前端：`localStorage["tender.customFields.<jobId>"]`，每次增删改立即写入（防刷新丢失）。
- 提交：生成/预览时放进 `custom_fields` 数组（见 5.6）。后端是否落库由后端决定，前端不依赖。

> 为什么不用 `fields.json`：那是仓库里的全局配置，多人共享；把用户字段写回去会污染所有人、并且引发 git 冲突。用户数据放 `data/`。

### 5.4 UI 设计

**入口（两处）：**

1. 左侧分组导航底部：`+ 添加字段`（次要按钮样式）。
2. 字段区工具栏右侧：`+ 自定义字段`。

**新增/编辑弹窗**（复用 `.dlg` 样式，参考 `projects.html` 里的弹窗写法）：

```
标题：添加字段
字段名   [____________________]   （必填，≤30 字，不得与现有字段名重复）
类型     [单行文本 ▾]            text / 多行文本 / 金额 / 日期 / 下拉
值       [____________________]
         （type=long_text 时是 4 行 textarea；select 时显示候选值输入 + 添加）
写入位置 ( ) 追加到文末「补充条款」
         ( ) 写入模板已有占位符  [选择占位符 ▾]   ← 选项来自模板 unmapped 清单
         （未匹配占位符为空时，该项置灰，提示「当前模板的占位符已全部匹配字段」）
                    [取消]  [保存]
```

校验规则（前端拦，后端兜底）：

| 规则 | 提示 |
|---|---|
| 字段名为空 | 「请填写字段名」 |
| 字段名与现有字段 `label` 或占位符重名 | 「已有同名字段，请换一个名称」 |
| 选了「写入占位符」但没选占位符 | 「请选择要写入的占位符」 |
| 金额类型输入非数字 | 允许留空；有内容时只允许数字、小数点、千分位逗号 |

**字段卡片**：渲染成与内置字段完全一致的 `.field`，差别只在头部：

```html
<span class="label">履约保证金比例</span>
<span class="tag t-info">自定义</span>
<span class="tpl">追加到补充条款</span>   <!-- 或 <span class="tpl">占位符：采购人邮箱</span> -->
<span class="spacer"></span>
<button class="btn small ghost">编辑</button>
<button class="btn small ghost">删除</button>
```

放在哪个分组：

- `target=append` 的，统一放新增的「自定义字段」分组，排在 `contract` 之后；若用户字段超过 5 个，在该分组内按创建时间排序。
- `target=placeholder` 的，若能匹配到某个内置字段的章节归属则并入该组，否则也进「自定义字段」组（v1 简化：全部进「自定义字段」组也可以，但要保证导航里有这一组）。

**统计**：进度条 `已就绪 X / Y` 包含自定义字段；分组导航里的 `自定义字段` 分组显示 `filled/total`。

**AI 起草按钮**不得覆盖自定义字段（`/suggest` 只针对内置缺失字段）。

### 5.5 与「删除内置字段」的区分

v1 **不支持**删除内置字段（删除会破坏模板回填）。若用户想表达「这项不适用」，用「清空」+ 生成时 `missing_mode=empty`。这一点在 UI 上不要给出误导性按钮。

### 5.6 生成的契约扩展（需后端实现）

`POST /api/jobs/{id}/generate` 请求体扩展为：

```json
{
  "values": { "项目名称": "…" },
  "missing_mode": "mark",
  "template_id": "tpl-20261104-a1b2c3",
  "custom_fields": [
    { "key": "cf_1", "label": "履约保证金比例", "value": "合同金额的 5%", "target": "append" },
    { "key": "cf_2", "label": "采购人邮箱", "value": "a@b.com", "target": "placeholder", "placeholder": "采购人邮箱" }
  ]
}
```

后端行为（写进契约，前端按此预期）：

1. `target=placeholder`：把 `value` 写入同名占位符，优先级等同 `values`（若 `values` 里已有同名键，以 `values` 为准）。
2. `target=append`：在文档末尾新增一节：

   ```
   补充条款
   ┌──────────────┬──────────────────────┐
   │ 履约保证金比例 │ 合同金额的 5%         │
   │ 现场踏勘时间   │ 2026-11-10 09:00     │
   └──────────────┴──────────────────────┘
   ```

   值为空的行不输出；全部为空则不生成这一节。
3. 字段超过 12 个时，后端可改为一条一段的「字段名：值」列表（前端不做假设，只保证数据正确）。

预览接口同样接受 `custom_fields`，并在 `blocks` 末尾体现这一节，保证「预览 = 生成的文档」。

### 5.7 合规红线

自定义字段是**人工输入**，不是模型抽取：

- 不得写入 `item.evidence`，不得伪造原文引文。
- 审核报告 / 结果 JSON 中若出现这些字段，`source` 必须是 `manual`，状态不能标成「已确认」或给置信度。
- 前端在卡片上不要显示「已抽取 xx%」这类标签，只显示「自定义」。

这条与项目硬约束「证据可回链」直接相关：模型产出的值必须有原文证据，人工填的值必须能追溯到人。二者不能混。

### 5.8 验收标准

1. 添加 3 个字段（1 个追加、1 个绑定占位符、1 个金额）→ 刷新页面后仍在。
2. 进度条与分组计数包含这 3 个字段。
3. 生成文档：末尾出现「补充条款」表格且内容正确；绑定的占位符位置被替换成填的值。
4. 删除其中一个字段 → 重新生成，文档里不再出现该内容。
5. 字段名重复/为空时被拦下，且弹窗不关闭。
6. 切到别的任务（不同 `jobId`），自定义字段互不串台。
7. 绑定占位符的下拉框在模板无未匹配占位符时置灰并有说明。

## 8. 接口没就绪时怎么开发

后端三个接口不会一开始就有。前端按下面的方式并行：

1. 在 `frontend/` 下放一份 `mock/` 目录（**仅本地开发用，PR 合并前删掉**），例如 `mock/templates.json`、`mock/preview.json`。
2. 页面里加一个开关，默认走真实接口：

   ```js
   var USE_MOCK = new URLSearchParams(location.search).has("mock");
   async function api(path, init) {
     if (!USE_MOCK) return fetch(path, init);
     var file = MOCK_MAP[path];           // path → mock 文件
     return new Response(JSON.stringify(await (await fetch(file)).json()), {
       status: 200, headers: { "Content-Type": "application/json" }
     });
   }
   ```

   访问 `http://127.0.0.1:8765/templates?mock=1` 即用假数据。
3. mock 数据要**覆盖边界**：空列表、20 个模板、`unmapped` 为空、`sections` 只有一个、表格有合并单元格、超长字段值。
4. 接口联调时逐项对 `frontend/README.md` 的契约表，不要以 mock 的形状为准。

## 10. 已知坑

| 坑 | 说明 |
|---|---|
| 一次只渲染一个分组 | `renderActiveGroup()` 会整体替换 `#groups` 的 innerHTML。任何「从 DOM 读全量值」的写法都会漏数据（见 P0-1）。值一律以 `state` + `item.value` 为准 |
| `_send_binary` 强制下载 | 所有二进制响应都带 `Content-Disposition: attachment`，iframe/`<embed>` 打不开。需要内联预览必须后端加参数，前端改不了 |
| `templates/compiled/` 是产物 | 不要为了预览去手改 compiled 里的文件，改源模板后由后端重跑 `scripts/prepare_template.py` |
| 中文占位符 | 占位符名是中文，作为 `values` 的键、`data-name` 属性都没问题，但拼进 HTML 属性前必须 `esc()` |
| 字段值可能很长 | 预览的 `segments` 单条文本可能上万字（如「采购需求」整段），渲染时 `white-space: pre-wrap; word-break: break-word`，不要截断 |
| 金额 | 前端只做展示与输入校验，**不做金额计算**；任何金额格式化以后端 `Decimal` 结果为准 |
| Windows 编码 | 页面文件必须存 UTF-8；PowerShell 里用 `>` 重定向生成文件可能写出 GBK，导致中文乱码 |
| 缓存 | 服务端下发 `no-store`，但页面内自己用 `localStorage` 时要带命名空间前缀，避免不同任务互相覆盖 |
| 任务 id 会过期 | 后端只保留最近 30 个任务（`KEEP_JOBS`），旧链接会 404，前端要按「任务不存在或已过期」提示，引导回 `/` 重新上传 |
